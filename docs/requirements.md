# 需求文件

本文件根據目前 SilverGuardian 專案程式碼推導，描述應用現有需求與可觀察到的產品行為。

## 產品目標

SilverGuardian 的目標是提供一個長者友善的行動工具，協助使用者：

- 判斷收到的訊息或截圖是否可能為詐騙。
- 用語音快速建立支出、備忘或行事曆記錄。
- 在疑似高風險詐騙時通知家人。

## 使用者角色

### 主要使用者

長者或需要簡化操作流程的使用者。

根據畫面設計推導，應用使用大字體、大按鈕與明顯顏色區分功能，目標族群應偏向需要低操作門檻的使用者。

### 次要使用者

家人或照護者。

家人不直接使用 App 主要流程，但可透過設定頁留下 Email，在高風險事件發生時接收通知。

## 功能需求

### R1. 首頁入口

應用需提供首頁，讓使用者快速進入：

- 語音記錄
- 圖片掃描
- 歷史記錄
- 設定
- 離開 App

### R2. 圖片掃描

應用需允許使用者：

- 使用相機拍攝圖片。
- 從相簿選擇圖片。
- 在 Android 上請求必要圖片或相機權限。
- 將圖片轉為 base64。
- 呼叫 AI 分析圖片內容。
- 顯示處理中狀態。
- 分析完成後導向結果頁。

### R3. 詐騙風險分析

圖片分析需產生以下資訊：

- OCR 或圖片文字摘要。
- AI 風險分數。
- 信心分數。
- 是否需要人工複查。
- 高風險證據。
- 低風險證據。
- 說明。
- 結論。

目前程式同時使用：

- OpenAI 回傳的 AI 分析結果。
- `ScanScreen.tsx` 中的本機關鍵字與規則引擎。

最終分數會根據規則分數與 AI 分數加權計算。

### R4. 風險結果頁

結果頁需顯示：

- 風險等級。
- 最終分數。
- AI 信心分數。
- 人工複查提示。
- 高風險證據。
- 低風險證據。
- 分析說明。
- 結論。
- Debug 資訊。

目前風險等級包含：

- 高風險
- 中風險
- 低風險
- 資訊不足

### R5. 高風險通知

當圖片掃描結果為高風險時，系統需嘗試通知家人。

目前實作方式：

- 從 AsyncStorage 讀取 `family_emails`。
- 過濾有效 Email。
- 使用 SendGrid API 寄送 HTML Email。
- 在結果頁顯示通知狀態。

### R6. 家人 Email 設定

使用者需能設定最多 3 組家人 Email。

設定需求：

- 輸入 Email。
- 驗證基本格式，至少包含 `@` 與 `.`。
- 儲存至 AsyncStorage。
- 顯示已儲存 Email。

### R7. 語音記錄

使用者需能按住按鈕錄音。

流程需求：

- 請求錄音權限。
- 開始錄音。
- 放開按鈕停止錄音。
- 將錄音檔送至 Whisper API。
- 顯示轉錄文字。
- 將轉錄文字送至 AI 分類。
- 顯示確認對話框。
- 使用者確認後儲存。

### R8. 語音分類

語音文字需分類為：

- 支出
- 備忘
- 行事曆

支出可能包含：

- 金額
- 分類
- 摘要

備忘可能包含：

- 內容
- 摘要

行事曆可能包含：

- 日期
- 時間
- 摘要

若分類為行事曆且有日期，系統會嘗試寫入裝置行事曆。

### R9. 歷史記錄

應用需保存並顯示語音記錄。

目前記錄欄位包含：

- id
- type
- content
- amount
- category
- date
- time
- summary
- createdAt

歷史頁需支援：

- 依建立時間排序顯示。
- 刪除單筆記錄。
- 空狀態顯示。

### R10. 使用次數限制

應用需限制每日 AI 呼叫次數。

目前程式碼顯示：

- 每日上限為 99 次。
- 使用 AsyncStorage 以日期 key 儲存當日次數。
- 圖片分析與語音轉錄前會呼叫檢查。

## 非功能需求

### 易用性

根據 UI 程式碼推導：

- 使用大字級。
- 使用大尺寸圓形或區塊按鈕。
- 使用紅色表示掃描或風險，綠色表示一般操作。
- 主要流程按鈕數量少，適合簡化操作。

### 隱私與安全

目前程式會處理：

- 錄音資料。
- 轉錄文字。
- 圖片或截圖。
- 家人 Email。
- AI 分析結果。

推測正式產品應需要：

- 清楚告知資料會送至第三方 API。
- 避免在正式環境輸出敏感 console log。
- 避免在手機端保存或暴露 API 金鑰。

### 可靠性

目前功能依賴外部服務：

- OpenAI API
- SendGrid API
- 裝置相機
- 裝置麥克風
- 裝置行事曆
- 本機 AsyncStorage

因此需求上應處理：

- 權限拒絕
- 網路失敗
- API 失敗
- JSON 解析失敗
- 第三方服務不可用

部分錯誤處理目前已存在，但仍可加強。

## 推測或尚未確認的需求

- 推測應用主要市場是繁體中文使用者，因為提示詞、介面文字與語音語言設定皆偏向中文。
- 推測圖片掃描主要針對 LINE 或通訊軟體截圖，因為部分畫面文字提及 LINE。
- 推測家人通知只在高風險圖片掃描結果觸發；目前沒有看到語音流程觸發家人通知。
- 推測目前沒有後端服務，所有 API 呼叫由 App 端直接發出。
