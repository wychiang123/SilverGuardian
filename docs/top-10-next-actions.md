# Top 10 Next Actions

本文件根據以下文件整理 SilverGuardian 未來最值得完成的前 10 項工作：

- `docs/project-status.md`
- `docs/mvp-analysis.md`
- `docs/agent-guide.md`

排序依據：

- 對 MVP 的直接影響
- 對商業價值的提升
- 對技術風險的降低
- 是否能讓未來 AI Agent 更安全地維護專案

## 立即執行

### 1. 修復 Jest 測試環境

商業價值：高  
技術風險：中  
開發時間：3 到 5 小時  
是否影響 MVP：是

原因：

- 目前 `npm test` 尚未穩定執行。
- 未來若要導入 Claude Code、Codex、OpenHands 自動維護，測試必須先能跑。
- 沒有測試基礎，後續重構核心防詐流程風險很高。

建議內容：

- 調整 Jest 設定，處理 React Navigation ESM。
- 建立 native module mock。
- 讓現有 App smoke test 穩定通過。

### 2. 拆出詐騙規則引擎並補單元測試

商業價值：極高  
技術風險：高  
開發時間：5 到 8 小時  
是否影響 MVP：是

原因：

- 詐騙風險判斷是 SilverGuardian 的核心價值。
- 目前 `runRuleEngine` 與 `computeFinalResult` 位於 `ScanScreen.tsx`，與 UI 混在一起。
- 缺少測試時，任何調整都可能導致高風險誤判或低風險誤判。

建議內容：

- 拆出 `scamRuleEngine`。
- 拆出 `scamRiskScoring`。
- 建立高風險、中風險、低風險、資訊不足案例。
- 建立白名單與高風險 anchor 測試。

### 3. 強化 OpenAI 回傳驗證

商業價值：高  
技術風險：高  
開發時間：3 到 5 小時  
是否影響 MVP：是

原因：

- 目前 OpenAI 回傳內容直接 `JSON.parse`。
- 模型回傳格式不穩時，圖片掃描與語音分類流程可能失敗。
- MVP 需要穩定處理第三方 API 的不確定性。

建議內容：

- 加入基本 schema validation。
- 處理 JSON parse 失敗。
- 對分數、風險等級、陣列欄位提供 fallback。
- 補錯誤案例測試。

### 4. 清理敏感 log 與正式使用者錯誤提示

商業價值：高  
技術風險：中  
開發時間：2 到 4 小時  
是否影響 MVP：是

原因：

- App 會處理圖片內容、語音轉錄、家人 Email 與 API 錯誤。
- 目前部分 console log 可能輸出敏感資料。
- Demo 或 MVP 測試時，錯誤訊息需要更友善、更少技術細節。

建議內容：

- 限制或移除敏感 console log。
- API 錯誤轉成使用者可理解訊息。
- 保留開發除錯資訊但避免正式介面曝光。

## 近期執行

### 5. 整理結果頁 MVP 體驗

商業價值：高  
技術風險：中  
開發時間：3 到 5 小時  
是否影響 MVP：是

原因：

- 結果頁是使用者判斷下一步的關鍵。
- 目前已顯示分數、證據、說明、結論與 debug 資訊，但正式 MVP 應更聚焦。
- 長者使用情境需要清楚、直接、可行動的提示。

建議內容：

- 高風險時明確提示不要匯款、不要點連結、先問家人。
- 資訊不足時提示重新拍攝或請家人協助。
- Debug 資訊改為開發模式或隱藏。

### 6. 將高風險通知流程從 ResultScreen 拆出

商業價值：中高  
技術風險：中高  
開發時間：3 到 5 小時  
是否影響 MVP：是

原因：

- 目前通知副作用由 `ResultScreen` 的 lifecycle 觸發。
- 未來畫面重繪、導覽或重試機制可能造成通知行為不清楚。
- 高風險通知是 MVP 閉環的一部分，應有清楚流程邊界。

建議內容：

- 建立 notification workflow。
- 明確定義通知狀態。
- 避免重複寄送。
- 補通知成功、失敗、無聯絡人測試。

### 7. 建立家人 Email 設定 service

商業價值：中  
技術風險：中  
開發時間：2 到 3 小時  
是否影響 MVP：是

原因：

- `family_emails` 目前由設定頁與通知 service 共同依賴。
- storage key 分散會增加維護成本。
- 家人通知是 MVP 必要功能，設定資料應集中管理。

建議內容：

- 建立 `settingsService` 或 `familyContactService`。
- 集中 Email 讀取、儲存、驗證。
- 補基本單元測試。

### 8. 建立後端代理服務設計

商業價值：高  
技術風險：高  
開發時間：4 到 8 小時，僅設計；實作需更多時間  
是否影響 MVP：間接影響，公開測試前必要

原因：

- 手機端直接持有 OpenAI 與 SendGrid API key 是高風險。
- 若要進入 Beta 或公開測試，後端代理幾乎是必要項。
- 但若只是內部 Demo，可以先設計、後實作。

建議內容：

- 定義 OpenAI proxy API。
- 定義 SendGrid notification API。
- 定義伺服器端 rate limit。
- 定義成本紀錄與錯誤追蹤需求。

### 9. 儲存圖片掃描歷史

商業價值：中  
技術風險：中  
開發時間：4 到 6 小時  
是否影響 MVP：否，但影響產品完整度

原因：

- 目前歷史記錄主要保存語音流程資料。
- 圖片掃描結果沒有看到保存機制。
- 未來若要讓家人回看或追蹤高風險事件，掃描歷史會很有價值。

建議內容：

- 定義 scan record 資料模型。
- 儲存風險等級、分數、結論、建立時間。
- 避免直接保存敏感圖片，除非有明確隱私設計。

### 10. 改善語音記錄流程並拆出 workflow

商業價值：中  
技術風險：中高  
開發時間：5 到 8 小時  
是否影響 MVP：否，屬於加分功能

原因：

- 語音記錄是長者友善的重要加值功能。
- 目前 `RecordingScreen.tsx` 同時處理錄音、轉錄、AI 分類、儲存與行事曆。

- 補 Whisper 與分類流程測試。
